# quizeDB — база вопросов для викторины

JSON-файлы с вопросами, разложенные по языковым папкам. Каждый файл — независимый набор вопросов
на своём языке (это не переводы: одинаковая структура и тема, но своё содержимое и своя культура).

```
data/
  ru/  <13 тем>    fr/  <13 тем>
  en/  <13 тем>    es/  <13 тем>
  zh/  <13 тем>    ar/  <13 тем>
```

## Письменность (проверяется автоматически)

| язык | разрешено | запрещено |
|---|---|---|
| `ru` | кириллица | латиница, CJK, арабица |
| `en`, `fr`, `es` | латиница (é è ê à ç, ñ á í ó ú ü) | кириллица, CJK, арабица |
| `zh` | иероглифы | латиница, кириллица, арабица |
| `ar` | **только арабица** | латиница, кириллица, CJK |

Поэтому века и числа пишутся словами: «девятнадцатый век», «le dix-neuvième siècle», «el siglo
diecinueve», 「十九世纪」, «القرن التاسع عشر». В `ar` любое иностранное имя транслитерируется
(باريس، لندن، شكسبير).

## Два способа группировать вопросы

**1. По типу вариантов («схожие варианты»)** — варианты в файле сущности одного вида, поэтому
«цех» ответа ничего не подсказывает:

* `names` — писатели, композиторы, художники, политики, режиссёры в одном файле; вопрос «с чьим
  именем связано X?», варианты — только имена людей (включая персонажей книг как элементы).
* `works` — обратная сторона: вопрос «какое из этих произведений создал X?», варианты — роман,
  опера, картина или фильм в одном списке.
* `places` / `dates` / `numbers` / `animals` / `colors` — ключ темы и есть тип варианта: страны,
  века, числа, животные, цвета.

**2. По предмету** — `cities`, `inventors`, `cuisine`, `mythology`, `holidays`, `tales`: обе стороны
однородны по виду (достопримечательности, изобретения, блюда…), работают в обычном режиме с
вопросами в обе стороны.

## Схема файла

```json
{
  "theme": "Великие имена",
  "questions": [
    {
      "text": "Имя какого человека связано с «Отцы и дети»?",
      "options": ["Александр Солженицын", "Карл Брюллов", "Михаил Глинка", "Лев Толстой"],
      "answer": ["Иван Тургенев"]
    },
    {
      "text": "Какие два произведения из списка написал Пётр Чайковский?",
      "options": ["Королевская регата", "Ирония судьбы", "Пустынник", "Кошкин дом", "Война"],
      "answer": ["Лебединое озеро", "Щелкунчик"]
    }
  ]
}
```

* `theme` — название темы на языке файла.
* `text` — текст вопроса.
* `options` — только НЕПРАВИЛЬНЫЕ варианты (обманки), 4–6 штук.
* `answer` — только ПРАВИЛЬНЫЕ варианты; **на вопрос может быть несколько правильных ответов**
  (массив из 1–2 элементов).

`options` и `answer` не пересекаются; игроку показывается объединение `options + answer`,
перемешанное в случайном порядке.

## Инварианты (проверяются автоматически)

1. JSON парсится; у каждого вопроса есть `text`, `options`, `answer`.
2. `options` — 4–6 уникальных строк.
3. `answer` — непустой массив строк, без дублей, не пересекается с `options`.
4. Тексты вопросов уникальны внутри файла и не повторяются между файлами.
5. В файле 100–150 вопросов.
6. Строки — на языке файла (см. таблицу письменностей выше).
7. Варианты пересекаются между вопросами: сущность бывает и ответом, и обманкой (порог — 40 %
   таких сущностей и не меньше 8 значений; темы «схожих вариантов» дают 100 %).
8. Диагностика: вопрос не должен содержать в собственном тексте свой ответ (`self-answering`).

## Как это устроено

JSON не пишется руками. На каждый файл есть модуль данных `tools/data/<lang>.<theme>.mjs` с
отношением «ключ → элементы», из которого генератор собирает вопросы:

* элемент → ключ («чей это предмет/заслуга?»), по одному вопросу на элемент;
* дополнительное отношение `secondary` (например, персонаж → автор), если задано;
* ключ → элемент(ы) («что принадлежит X?»), часть — с двумя правильными ответами.

Режимы: `keyQuestions: 0` — только «элемент → ключ» (нужно ≥100 элементов); `itemQuestions: 0` —
только «ключ → элемент» (нужно ≥100 ключей, либо `questionsPerKey: 2` при ~60 ключах);
`multiEvery: 1|2` — как часто вопрос имеет два ответа. Все обманки берутся только из ЧУЖИХ ключей,
поэтому правильный вариант не может попасть в `options`; пересечение вариантов возникает само.

## Команды

```bash
node tools/generate.mjs --all          # пересобрать все темы всех языков
node tools/generate.mjs fr.works       # одна тема (lang.theme)
node tools/generate.mjs fr             # все темы одного языка

node tools/validate.mjs                # проверить все файлы (или fr.works / fr)
python tools/validate_independent.py   # независимая реализация тех же проверок
node tools/check_grammar.mjs           # ru-шаблоны: {v} не должен требовать косвенного падежа
node tools/check_fr_elision.mjs        # fr-шаблоны: «de Athènes» → «d'Athènes»
node tools/leaks.mjs                   # элементы, раскрывающие свой же ключ
node tools/qa.mjs [--sample N]         # статистика, диагностика и выборка вопросов
node tools/report.mjs                  # таблица по всем темам и языкам
```

`tools/THEME_SPEC.md` — контракт для автора новой темы: схема модуля, объём, честность обманок,
чистота языка, грамматика шаблонов, чек-лист, разбор ловушек (двойное авторство, эпонимы,
«вариант повторяет имя ключа»).

## Как добавить тему

1. Создать `tools/data/<lang>.<slug>.mjs` для каждого языка по `tools/THEME_SPEC.md`.
2. `node tools/generate.mjs <lang>.<slug>` → `data/<lang>/<slug>.json`.
3. `node tools/validate.mjs` → `ALL CHECKS PASSED`, `node tools/leaks.mjs` → `OK`.
